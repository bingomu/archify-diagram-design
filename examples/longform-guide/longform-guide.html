怎样把一篇长文做成可视化攻略？

长图

答

结论

先定结论，再让 Archify 出图，最后只用 CSS 换肤：大约 40 分钟，就能得到一页能点、能导出长图的攻略。

  1. 读者先看结论，再按需展开流程图和步骤。
  2. 流程、时长和清单都由 Archify 原生渲染，可以缩放和联动高亮。
  3. 换肤只改颜色、字体和阴影，不碰交互脚本。
  4. 交付前用浏览器验收导出菜单，坏了就回退原件。

适用于演示稿：以一篇约 5000 字的教程为例；各环节时长为估算

1

从长文到一页攻略，要走哪几步？

图的结构
  • 通读长文 read
  • 定一句结论 verdict
  • CSS 换肤 skin
  • 写 Archify 草稿 draft
  • 校验并生成 finalize
  • 导出可用? check
  • 回退原件 rollback
  • 交付 HTML deliver
  • check → deliver · 是
  • check → rollback · 否
  • draft → finalize
  • finalize → skin
  • read → verdict
  • rollback → skin · 保守重试
  • skin → check
  • verdict → draft
  1. 通读长文 ↗

    标出步骤、分支、等待时长和必须核对的事项。截图每个阶段最多留 2 张。

  2. 定一句结论 ↗

    用一句话回答读者最关心的问题，再配不超过 4 条理由。

  3. 写 Archify 草稿 ↗

    把流程写成 @workflow，时长写成 @timeline，分步写成 @steps。

  4. 校验并生成 ↗

    运行 finalize explainer。失败时只按诊断提示改草稿，最多两轮。

  5. CSS 换肤 ↗

    在 </head> 前插入 dd-skin 样式：珊瑚强调色、纸色底、无阴影。

  6. 导出可用? ↗

    用无头浏览器打开页面，确认导出菜单仍有 PNG、WebP、JPG 三项。

  7. 回退原件 ↗

    交互或导出坏了，就回到 finalize 原件，只保留变量覆盖再试。

  8. 交付 HTML ↗

    交付单个 HTML 文件，离线也能打开。

每个环节大概花多久？

图的结构
  • 开始通读长文 t-read
  • 结论定稿 t-verdict
  • 开始写草稿 t-draft
  • finalize 通过 t-final
  • 换肤完成 t-skin
  • 导出验收 t-check
  • 交付 HTML t-ship

时长是估算

时间线按一篇约 5000 字的教程估算，实际取决于原文长度和截图数量。 写草稿通常最花时间，约占总时长的 40%。

3

换肤改了什么，没改什么？

项目Archify 默认换肤后
强调色蓝色克制使用珊瑚 #bf4520
底色与正文默认配色纸色 #f5f5f5，墨色 #2d3142
阴影有轻阴影更干净全部去掉
圆角默认圆角不超过 8px
交互与导出完整硬约束完整保留
内联脚本原样禁止改写不改一行

硬规则

换肤只能新增一段 <style id="dd-skin">。 不要删改 Archify 的内联脚本，也不要往结论区塞静态主图。
